[Added] - New `pie-dropdown` component: a form-associated dropdown supporting single and multi selection, an optional search field for filtering options, loading and no-results states, and full keyboard and screen reader support (single select uses a listbox with roving focus; multi select uses checkbox rows inside a checkbox group). The popover always renders below the field, never above it. Non-searchable fields open on click or keyboard focus (focus-open never moves focus — the arrow keys move focus into the option list, never `Tab`, so the field's other controls stay reachable); searchable fields open on the first keystroke, the arrow keys or a click — not on focus, so the `aria-expanded` state change never chases and interrupts the field's focus announcement. The listbox stays mounted (hidden while closed) after first open so re-opens do not re-insert it and interrupt screen reader announcements. Typing in searchable variants always filters (typing while focused on an option returns focus to the search field and filters); selecting from filtered results shows the selection in the field (already present when focus returns, so screen readers announce it) and clears the search, so the next open starts from the full list. In multi-select variants with a selection, the count chip's close button is the first tab stop (the trigger is skipped while the chip is shown), so keyboard users can clear every selection and Tab straight to the options. The clear affordances (the chip's close button and the single-select clear button) append the field's accessible name to their own for screen reader context, e.g. "Clear all 2 selections, Meal". The selected option's tick uses the brand content colour. All copy is prop-driven: the count chip text (`selectedCountText`), the search result announcement (`optionsAvailableText`) and the required-and-empty validation message (`noSelectionText`) accept `{count}` placeholders / custom strings, and the helper text below the field (`assistiveText`) is announced as the field's accessible description via a plain text element, so screen readers read it on focus.
[Added] - `RovingTabindexController` exported from `pie-webc-core` for arrow-key, Home/End and type-ahead navigation across a group of items. An `isTabbable` option removes the group from the page tab sequence entirely, and an `isTypeaheadEnabled` option disables type-ahead, for combobox-style popovers where the field is the single tab stop and printable characters belong in the textbox.
[Added] - New `option` interaction type on `pie-list-item`: the item becomes an `option` row with interactive states, for use inside listbox-style containers such as the dropdown popover; selection state and focus remain owned by the container.
[Added] - `pie-dropdown` re-exported from the `pie-webc` umbrella package.
